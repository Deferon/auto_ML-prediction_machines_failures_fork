# Прогноз отказов оборудования — Яньшин А.

## 1. Задача и происхождение

Форк группового учебного проекта. Автор доработок форка: **Яньшин А.**
Цель — оценивать риск отказа оборудования по телеметрии.

## 2. Рефакторинг кода

- Общие для обучения и инференса преобразования, сохраняющие порядок строк.
- Валидация CSV: обязательные колонки, пустые значения, типы, бесконечности, дубликаты.
- Флаги известных отказов исключены из входов модели; схема признаков версионируется.
- Типизация, логирование, параметры CLI и настройка путей через окружение.
- MLflow сохраняет историю экспериментов без автоматического удаления базы.
- Фиксированные пороги риска и устойчивый расчёт PSI.

## 3. Poetry и виртуальное окружение

- Python 3.11/3.12, отдельная .venv внутри проекта.
- pyproject.toml описывает пакет и зависимости, poetry.lock фиксирует версии.
- poetry.toml и lock-файл хранятся в Git; .venv исключена.
- Восстановление: poetry sync --with dev.

## 4. pre-commit и проверки

- Ruff: ошибки, импорты и форматирование.
- Mypy: типы рабочего кода.
- Проверки YAML/TOML, lock-файла, конфликтов слияния и пробелов.
- pytest: регрессионные тесты и полный цикл train → save → load → predict.
- GitHub Actions: Linux/Windows, Python 3.11/3.12, сборка пакета и Docker.

## 5. Запуск

```bash
poetry sync --with dev
poetry run pre-commit install
poetry run pre-commit run --all-files
poetry run pytest -q
poetry run ml-train --smoke
poetry run ml-predict
```

## 6. Ограничения и дальнейшая проверка

Старая PPTX и example-отчёты содержат исторические метрики группового проекта.
Новая модель требует отдельной оценки: результаты записываются в artifacts/metrics.json.
Перед применением на предприятии нужны временная/групповая валидация, калибровка
вероятностей и подбор порогов по стоимости ошибок.
